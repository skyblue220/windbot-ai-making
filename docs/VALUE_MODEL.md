## 1. 원칙

1. **가치는 효과의 기능(의미) 종류마다 기본값을 준다.** 카드의 가치는 그 카드가 가진 기능들의 합으로 계산된다. (확정)
2. **기본값은 아래 2장의 표를 따른다.** (확정)
3. **학습은 카드 단위로 값을 고친다.** 같은 "서치"라도 카드 종류와 테마마다 그 효과를 가진 카드의 수, 기능의 조합, 서브 스타터 여부가 다르므로, 학습 과정에서는 **해당 효과를 가진 그 카드에만** 가치를 수정한다. 기능별 기본값 자체는 바꾸지 않는다. (확정)
   - 이유: 앞으로 Ryzeal 외의 다른 테마에도 같은 기본값 표를 출발점으로 쓴다. 한 테마의 학습 결과가 기본값을 바꾸면 다른 테마의 출발점이 오염된다.
4. **값은 상태에 따라 다시 계산된다.** 같은 카드라도 효과를 이미 썼는지, 대상이 덱에 남아 있는지, 필드에 무엇이 있는지에 따라 가치가 달라진다(3장의 재귀).

```
효과의 가치 = 기능별 기본값 (모든 테마 공통, 고정)
            + 카드별 학습 보정값 (그 카드의 그 효과에만 적용, 처음엔 0)
```

## 3. 재귀: 카드가 불러오는 카드들의 가치 — 유한 등비수열 합 (확정, 구현됨)

극한(무한 급수 + 임의의 깊이 제한) 대신, **실제 자원으로 정해지는 단계 수 n까지의 유한한 합**으로 계산한다. (2026-11-07 변경, 구현 커밋 `7a726b5`)

### 3.1 식

```
S = Σ_{k=0}^{n} γ^k × (기본값_k + 보정값_k)
```

- k번째 단계 = 경로의 k번째 효과 사용. 각 단계는 앞 단계 효과가 불러온 카드의 효과다.
- 같은 단계에서 여러 갈래가 있으면 합이 가장 큰 경로를 택한다.
- **γ (다음 단계 할인율)**: 0.7 (`agent_values.json`에서 변경 가능)
- 기본값이 모두 a로 같다고 보면 닫힌 식 `S ≈ a × (1 − γ^(n+1)) / (1 − γ)`. 실제 계산은 단계마다 기본값이 달라서 경로를 따라 정확히 더한다.

### 3.2 n을 정하는 것 (상태에서 계산)

경로가 다음 단계로 이어지려면 아래를 모두 만족해야 한다. 하나라도 안 되면 그 경로는 거기서 끝난다.

1. **덱에 대상이 남아 있다**: `덱에 남은 장수 = ydk의 매수 − (패·필드·묘지·제외에서 보이는 내 카드 장수)`. 경로에서 덱의 카드를 꺼낼 때마다 1씩 줄인다. Ryzeal 몬스터처럼 3장 넣은 카드는 3장까지 이어질 수 있고, 이미 패나 필드에 있는 만큼 줄어든다.
2. **효과가 아직 쓸 수 있다**: 이번 턴 이미 쓴 1턴 1번 효과(엔진 이벤트로 기록된 것)와, 경로 앞쪽에서 이미 쓴 효과는 다시 쓸 수 없다. 같은 카드가 경로에 다시 나와도 같은 효과는 0이므로, `Ice → Sword → Ext → Ice` 같은 고리는 자연스럽게 끝난다.
3. **계기가 맞는다**: 특수 소환으로 도착한 카드는 "특수 소환 성공 시" 효과만, 일반 소환한 카드는 "일반 소환 성공 시" 효과만 켜진다. 필드에 있으면 기동 효과도 쓸 수 있다.
4. **패에 온 카드는 꺼낼 수단이 있어야 한다**: 룰 특수 소환(그 효과가 안 쓰였고 조건이 맞을 때, 경로에서 먼저 필드에 나온 카드도 조건에 포함) 또는 남은 일반 소환권(레벨 4 이하). 패의 마법은 발동 효과로 이어진다.
5. **효과에 대상이 있다**: "묘지에서 특수 소환"처럼 대상을 고르는 효과는 대상이 없으면 발동할 수 없으므로 0이다.

- 한 효과 안에서 "A 또는 B를 불러온다"(예: Plugin)는 가장 큰 것 하나만 친다. 소재 부착 같은 부가 기능은 더한다.
- 이전 안의 λ(이미 쓴 효과 보정)는 이번 턴 계산에서는 쓰지 않는다. 이미 쓴 효과는 0이다. 다음 턴 이후의 가치를 칠 때 다시 정한다.
- 안전장치: 경로 최대 12단계, 탐색 예산 20,000 노드. 실제 길이는 자원으로 정해진다.

### 3.3 계산 결과 예시 (실제 출력, γ = 0.7)

패: Ice, Sword, Ext, Ash, Plugin / 필드·묘지 비어 있음 / 일반 소환 가능 / 덱: Ice 2, Sword 2, Ext 2, Star 1, Node 1 …

| 패 카드 | 가치 | 경로 |
|---|---|---|
| Ice | 85.9 | Ice ② 덱 특수 소환 40 → Ext 서치 30γ → Sword 룰 소환 20γ² → Sword 서치(Ice) 30γ³ → Ice 룰 소환 20γ⁴ |
| Ext | 65.6 | Ext 서치 30 → Sword 룰 소환 20γ → Sword 서치(Ice) 30γ² → Ice 룰 소환 20γ³ |
| Sword | 44 | Sword 서치(Ice) 30 → Ice 룰 소환 20γ |

(검증 수정 후 값. Star는 필드에 소재가 없어 룰 소환이 불가능하므로 경로에서 빠졌다.)
| Ash | 0 | 선공 1턴 경로에 기여 없음 (상대 턴 축) |
| Plugin | 0 | 묘지·제외가 비어 있어 발동 불가 (커밋 `edea2f3` 이전에는 "덱에서 특수 소환"으로 잘못 분류되어 95.7이었음) |

- 경로에서 Ice가 Ext를 덱에서 꺼내면 덱의 Ext가 1장 줄고, 이미 쓴 Ice ②는 다시 나오지 않는다.
- Sword의 룰 소환 조건(필드에 라이제올)은 경로에서 먼저 필드에 나온 카드로 충족된다.

### 3.4 알려진 한계

- **Star 룰 소환의 코스트(엑시즈 소재 1개 제거)**가 DB에서 추출되지 않아, 필드에 Xyz가 없어도 가능한 것으로 계산된다. 위 예시의 Star 단계는 실제로는 불가능할 수 있다.
- **Ext 서치의 부재 조건, Node 룰 소환 조건**은 미해석이라 충족된 것으로 본다.
- 엑시즈 소환(소재 2장 → 결과 카드)은 아직 경로에 넣지 않았다.
- 세트한 마법·함정은 그 턴 경로를 잇지 않는다(함정은 그 턴 발동 불가).
- 코스트(패·필드 → 묘지)는 내 패·필드에서 가장 가치가 낮은 카드의 기능 합으로 계산한다(재귀 없이).

### 3.5 구현과 확인 방법

- 코드: `Agent/Knowledge/ValueModel.cs`(계산), `Agent/DuelZoneView.cs`(듀얼 중 위치), `Agent/CardDbFactory.cs`(가중치 파일, 오프라인 확인)
- 가중치 파일: `ProjectIgnis\Windbot\agent_values.json` (`gamma`, `maxSteps`, `base.*`, `offset.<카드ID>:<효과번호>`). 없으면 기본값으로 만들어진다.
- 듀얼 중: 선택지마다 `info`에 가치와 경로, `estimate`에 숫자가 기록되고, `_state.md`에 턴마다 패 카드 가치가 나온다. **판단은 아직 무작위다.**
- 오프라인: `WindBot.exe AgentDbDump=AI_Ryzeal AgentDbOut=<파일> AgentDbHand=<카드ID,카드ID,...>`

## 5. 학습에서 바뀌는 것과 바뀌지 않는 것

| 항목 | 학습으로 바뀌는가 |
|---|---|
| 2장의 기능별 기본값 | 아니오. 모든 테마의 공통 출발점으로 고정 |
| 카드별 학습 보정값 (그 카드의 그 효과) | **예. 학습은 이 값만 고친다** |
| γ, λ, 깊이 | 미정. 실험으로 정한다 (제안) |

- 보정값은 카드 ID + 효과 번호(설명 번호) 단위로 저장한다. 덱이나 테마를 바꿔도 다른 카드의 값에는 영향이 없다.
- 보정값은 코드 밖의 파일에 저장해서, 학습이 쌓여도 코드를 고치지 않는다.
- 학습 신호: 예측한 행동 후 가치와 실제 결과(다음 상태, 턴 종료 필드, 승패)의 차이. 반복 대전으로 차이가 나는 쪽의 카드 보정값을 고친다.

## 6. 같이 정해야 할 규칙 (제안)

1. **계기 조건** (구현됨, 3.2의 3번): 효과가 언제 켜지는지가 재귀 경로를 제한한다.
   - Ice ②는 일반 소환 시에만 발동한다. 다른 효과로 특수 소환된 Ice에서는 ②가 켜지지 않고, 일반 소환권을 이미 썼으면 막힌다.
   - Sword ②, Ext ②는 일반·특수 소환 모두에서 켜진다.
   - 대상이 어떻게 도착하느냐(덱에서 특수 소환 / 패로 서치 후 소환)에 따라 다음 단계에서 쓸 수 있는 효과가 달라야 한다. DB에 계기 정보가 있으므로 그대로 쓸 수 있다.
2. **서치로 패에 온 카드**: 다음 단계에 쓰려면 소환 수단(룰 특수 소환 조건 충족, 또는 남은 일반 소환권)이 필요하다. 수단이 없으면 "패에 있는 자원" 가치만 친다.
3. **엑시즈 소환**: 필드의 몸 2장이 결과 카드 1장이 된다. 결과 카드의 가치에서 소재 2장의 필드 가치를 빼서 계산한다.
4. **상대 턴 상호작용**(파괴, 무효, 핸드트랩): 7장의 방해 가치로 평가한다.

### 7.1 게임 목표와 덱 구성 목표

### 7.5 선공 턴 평가 (구현됨, 커밋 `e048b09`)

```
계획 가치 = Σ γ^k × (각 행동의 기능 가치)              ← 3장의 흐름 가치
          + 턴 종료 시 상대 턴에 쓸 수 있는 방해의 가치  ← 패의 핸드트랩 + 세트한 함정 + 필드 (소재 수 반영)
          + 후속: 턴 종료 시 패에 남은 카드의 다음 턴 가치 (아래)
          − 효율 감점 × 처음 패에서 쓴 카드 수   ← 후속 항으로 대체, 기본값 0
```

**후속 가치 (2026-11-07)**: 패에 남긴 카드는 다음 턴의 자원이다. 이번 턴에 같은 이름의 효과를 이미 써서 지금 가치가 0인 카드(예: Ice로 덱의 Sword를 불러온 뒤 패의 Sword)도 다음 턴에는 1턴 1번이 풀린다.
- 다음 턴 가치 V_next = 3장의 패 카드 가치 계산을 **1턴 1번 사용 기록을 비우고**(1듀얼 1번은 유지), 일반 소환 가능으로 돌린 값. 덱·묘지·필드는 지금 그대로.
- k번째 장의 후속 = `follow.discount`(0.3) × V_next × `follow.duplicate`(0.3)^(k−1). 다음 턴에도 같은 이름의 1턴 1번은 한 번이라 두 번째 장부터는 크게 깎는다.
- 쓰는 곳: ① 턴 계획의 턴 종료 평가(패에 남은 카드 합) ② 코스트·버리기로 고를 때 패 카드의 가치(지금 가치와 후속 중 큰 값, 여러 장이면 마지막 한 장의 후속).
- 그래서 "레벨 4가 하나 모자라 엑시즈를 못 하는" 경우는 규칙 없이 비교로 정해진다: 지금 써서 늘어나는 방해 가치가 남겼을 때의 후속보다 크면 쓴다.
- 0.6으로 시험하니 선공에서 Bonfire를 아끼고 Duo Drive 없이 끝내는 계획이 이겼다. 후속은 보정이라 끝 보드보다 훨씬 작게 둔다. 효율 감점과 같은 것을 두 번 세므로 효율 감점은 0으로 바꿨다(`agent_values.json`의 `efficiencyPerHandCard`).

예: Detonator(소재 2) + Cross가 필드에 있고 패에 Ash가 남은 경우의 방해 → Detonator ② 30×2 + ③ 30 + Cross ③ 37 + Ash 47 = 174

**턴 계획 탐색** (`Agent/Knowledge/TurnPlanner.cs`)
- 한 줄의 연쇄가 아니라 **한 턴 동안의 행동 조합**을 탐색한다: 일반 소환, 패의 룰 특수 소환, 패의 마법 발동(필드 마법 포함), 필드 몬스터의 기동 효과, **엑시즈 소환**(레벨 N 몬스터 2~3장, 소재 조건 확인), 그리고 도착할 때 켜지는 유발 효과.
- 코스트: 패에서 가장 가치가 낮은 카드(핸드트랩은 방해 가치까지 쳐서 잘 버리지 않음) / 엑스트라 덱 코스트는 묘지로 갔을 때 효과가 있는 카드(Eclipse Twins, Aggregator) → 쓸모가 적은 Xyz 순.

### 7.6 판단 연결 (커밋 `375dd57`)

`ValuePolicy`가 각 선택지의 가치(estimate)로 고른다. 가치가 없는 선택지는 가치가 있는 선택지가 하나라도 있으면 고르지 않는다.

| 요청 | 가치 | 고르는 방법 |
|---|---|---|
| 메인 페이즈 행동 | 그 행동으로 시작하는 최선 계획의 가치. 엔드 페이즈 = 지금 멈출 때의 가치, 배틀 페이즈 = 그보다 +1, 계획이 세트로 치는 함정 세트 = +1 | 최대 |
| 배틀 페이즈 | 공격 1, 나머지 0 | 최대 (공격으로 LP를 0으로) |
| 자기 카드의 임의 유발 (예/아니오) | 예 1, 아니오 0 | 발동 |
| 체인 | 자기 유발 2. 상대가 방금 체인했으면 내 방해 효과는 방해 가치, 패스 0. 아니면 패스 1 | 최대 |
| 카드 선택 (서치·특수 소환·세트 대상 등) | 내 카드의 현재 가치 (안 쓴 기능 + 방해 가치) | 높은 것 |
| 카드 선택 (코스트·버리기·묘지로·제외·릴리스·엑시즈 소재·소재 제거) | 위와 같음 | **낮은 것** |
| 존, 표시 형식, 선언, 합계 등 | 없음 | 무작위 |

- **탐색**: 확률 `explore`(기본 0.1, `agent_values.json`)로 가치와 무관하게 무작위로 고른다. 지금 가치로는 고르지 않을 행동의 결과도 기록에 남기기 위해서다(학습 재료). 로그의 `explored: true`가 그 결정이다.
- 상대가 체인할 때마다 방해를 쓰는 단순한 규칙이라, "언제 아껴 둘지"는 아직 판단하지 않는다(상대 모델과 함께 P3).

### 7.7 선공/후공 통합 가치표 (2026-11-07 합의, 구현 전)

한 효과에 두 역할을 둔다.
- **방해**: 상대 턴에 상대 전개를 막는다 (7.2~7.4의 값 그대로).
- **돌파**: 내 턴에 상대가 세운 방해를 치우거나, 상대 방해에 응답해 막는다.

**턴 보정**
- 선공: 돌파 ×0.4. 다음 내 턴에나 쓰므로 반 이상 줄인다. 방해는 ×1.0.
- 후공: 방해 ×0.9. 내 턴에 상대 방해를 막는 데도 쓰고, 다음 상대 턴의 방해로도 남으므로 거의 유지한다. 돌파는 ×1.0.
- 한 번 쓰면 한 역할만 하므로 효과의 값은 두 역할 중 큰 쪽이다.
  - 선공 값 = max(방해, 돌파×0.4)
  - 후공 값 = max(방해×0.9, 돌파)
- 배틀 페이즈 한정 보정(×0.5)은 방해에만 적용한다. 돌파는 원래 공격하려고 쓰는 것이라 깎지 않는다.

## 8. 아직 정하지 않은 것

- γ 값 (현재 0.7, 파일에서 변경 가능)
- 다음 턴 이후의 가치를 칠 때의 보정(이전 안의 λ)
- 카드별 보정값의 저장 형식과 학습 갱신 방식(학습률, 갱신 시점)
- 미해석 효과와 DB에서 빠진 카드의 보강 순서
- 방해 평가의 효율 감점 확정값 (현재 임시 10)
- 3장의 흐름 가치에서 "파괴/무효" 기능은 2장의 단일값 35를 쓴다. 턴 종료 방해 평가(7.5)는 7.2의 세분값을 쓴다.
