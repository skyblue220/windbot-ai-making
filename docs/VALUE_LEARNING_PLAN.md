# 카드 수치를 대결 결과와 상황으로 조정하기 — 계획 (2026-11-13)

## 0. 목표와 규칙

- **이번 조정이 마지막 수동 조정이다.** 이후 카드에 붙은 수치(카드 id가 들어간 값)는 사람이 넣거나 고치지 않는다. 대결 기록에서 계산한 갱신만 바꾼다.
- 기준은 VALUE_MODEL.md 합의를 따른다.
  - 기능 종류별 기본값(덱 특수 소환 40, 서치 30, 효과 무효 등)은 모든 테마가 공유하고 고정이다.
  - 학습이 바꾸는 것은 **카드(효과)별 보정값**뿐이다. 다른 테마의 출발점을 깨끗하게 두기 위해서다.
- 사람이 하는 일:
  - Lua에서 읽을 사실(특징)을 늘리기
  - 상황 신호 정의
  - 갱신 규칙과 안전 범위
  - 새 수치를 받아들일지 평가 기준
- 사람이 하지 않는 일: 카드 하나의 숫자를 맞추기.

## 2. 단계

### 0단계 — 마지막 수동 조정: 카드별 직접 입력 제거

`agent_values.json`에 카드 id가 붙은 수치 30개(`ib.` 기본값, `is.` 범위, `ia.` 가산, `ibt.` 배틀 한정)가 있다. 이것을 없앤다.

1. 각 항목이 표현하던 것을 Lua에서 읽는 사실로 바꾼다.
   - 배틀 페이즈 한정: condition의 `Duel.IsBattlePhase()`
   - 상대 몬스터 효과만: `re:IsMonsterEffect()`, `ep~=tp`
   - 무효 종류: 카테고리
   - 소재 떼기 비용과 횟수 제한
2. 같은 효과를 여러 번 쓸 수 있을 때(N104 ①: 소재 3, 횟수 제한 없음) 두 번째 사용부터는 "사용 기회가 실제로 올 확률"을 곱한다. 이 계수는 공유 고정값이다.
3. 바꿀 수 없는 항목은 목록으로 남겨 사용자에게 보인다. 그 항목의 카드 보정값은 0에서 시작한다.
4. 오프라인 덤프 전후 비교를 하고, 회귀 시험을 다시 돌린다.

완료 기준: `agent_values.json`에 카드 id가 붙은 수치가 0개. N104 ①이 배틀 페이즈 한정으로 읽히고, 메인 페이즈 카드를 막을 수 있는 목록에서 빠진다.

### 1단계 — 값 분해 기록

학습은 "어느 수치가 이 판단에 얼마나 들어갔나"를 알아야 한다. 지금 로그는 추정값과 설명 문자열(`info`)만 남긴다.

- 선택지 추정값마다 항목을 구조화해 jsonl에 남긴다(`terms`). 각 항목은 이렇게 생겼다.
  - `{kind: 흐름|턴종료방해|후속|전투|효율|상대드로우, card, effect, base, offset, count, value}`
- 계획의 끝 필드 방해는 카드 효과별로 남긴다(예: N104 ① 3회 × 19).
- 헤더에 가중치 파일 버전(해시)을 넣는다. 그러면 어느 수치로 둔 판인지 안다.

완료 기준: 한 판의 로그만으로 각 결정의 추정값을 항목 합으로 다시 만들 수 있다.

### 2단계 — 결과와 상황 신호

예측과 실제를 효과 단위로 짝지은 **결과 기록**을 만든다. 엔진 메시지와 체인 기록은 이미 있다(`message`, 상태 기록의 체인 줄).

1. **우리 방해 (상대 턴):** 턴 종료에 예측한 효과마다 다음을 남긴다.
   - 실제로 썼는지
   - 무엇을 막았는지(상대가 잃은 값은 OpponentLoss로 계산)
   - 쓰기 전에 제거됐는지
   - 안 쓰고 남았는지
2. **우리 전개 (우리 턴):** 계획 단계마다 실제로 처리됐는지, 상대의 어떤 카드에 막혔는지, 막힌 뒤 남은 값.
3. **상대 드로우 감시:** 예측한 드로우 장수와 실제 장수.
4. **전투:** 예측한 파괴와 피해, 실제 결과.
5. **듀얼 결과:** 승패와 종료 턴. 신호가 드물어서 나중 단계에서 쓴다.

완료 기준: 이번 로그 6개에서 위 기록이 자동으로 나온다. 예: "N104 ① 예측 57, 사용 0", "Detonator ① 예측값 / 실제: Ice ② 막음".

### 3단계 — 갱신 규칙 (처음에는 단순하고 검토 가능하게)

**3a. 상황 보정 (먼저):** 카드 효과별 보정값을 실제 값과 예측의 차이로 옮긴다.
- 보정값 ← 보정값 + η × 평균(실제 − 예측)
- 표본이 n판 이상일 때만 바꾼다.
- 한 번에 바뀌는 폭과 전체 범위를 제한한다(예: 기본값의 ±100%).
- 예: N104 ①은 여러 판에서 사용 0이 쌓이면 보정값이 내려간다. 사람이 숫자를 고치지 않는다.

**3b. 결과 보정 (대량 대전 뒤):**
- 턴 종료 상태의 값이 다음 턴 이후의 실제 결과(최종 승패 포함)를 맞히도록 보정값을 갱신한다(TD 방식).
- 이것이 강화학습 부분이다. 표본이 많이 필요해서 4단계 뒤에 한다.

**저장:**
- 사람이 검토하는 구조·기본값은 `agent_values.json`에 둔다.
- 학습만 쓰는 카드 보정값은 `agent_values.learned.json`에 둔다.
- 갱신할 때마다 변경 기록(근거 판 수, 예측·실제 평균, 전→후)을 남겨, 버전 단위로 되돌릴 수 있게 한다.

### 4단계 — 대량 대전과 평가

- 봇끼리 자동으로 대전하는 실행 수단을 만든다. 지금은 사람이 방을 열어 한 판에 1~1.5분 걸린다.
- 같은 시작 패로 짝지은 비교를 위해 `dontShuffleDeck`이나 시드 고정을 조사한다.
- 새 보정값 버전은 이전 버전과 미러 대전 N판을 해서 승률이 나빠지지 않을 때만 받아들인다.
- 자가 대전에서는 탐색(`explore` > 0)을 켜서, 평소 고르지 않는 선택의 결과도 모은다.

## 3. 순서와 바로 다음 할 일

0단계 → 1단계 → 2단계 → 3a를 지금 하는 수동 대전 로그로 시작 → 4단계 → 3b.

바로 다음은 0단계다. 30개 항목을 Lua 특징으로 바꾸는 표를 먼저 만들어 보이고, 바꿀 수 없는 항목을 확인받은 뒤 지운다.

## 4. 열린 문제

- 공유 계수(`int.battle_factor`, 두 번째 사용 계수 등)도 학습 대상인지. VALUE_MODEL.md 합의대로라면 고정이다. 카드 보정값만으로 맞지 않는 것이 보이면 다시 논의한다.
- 상대 덱 카드의 보정값: 상대 쪽 예측(상대 방해 값)도 같은 방식으로 실제와 비교할 수 있다. 미러 대전에서는 같은 카드라 자연스럽게 공유된다.
- 표본 수 n과 η의 처음 값: 대량 대전 속도를 본 뒤 정한다.
