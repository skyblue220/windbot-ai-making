# 판단 입력: 하나의 전체 상태 (2026-11-13)

계기: 실전에서 상대 필드에 Detonator가 있는데도 Ext ① 코스트로 Eclipse Twins를 보냈다(GRAVE_PAYOFF.md 7.7). 원인 중 하나는 결정 지점마다 상태를 따로 만들었다는 것이다. 계획기는 상대 몬스터가 든 스냅숏(`PlanSnapshot`)을 썼고, 카드 선택·제거 대상 가치·엑시즈 즉시 소환·세트 판단은 우리 쪽만 든 스냅숏(`_zones.Snapshot()`)을 썼다. 같은 판인데 판단마다 보는 정보가 달랐다.

이제는 모든 판단이 **같은 전체 상태 하나**를 읽는다(`DuelZoneView.Snapshot`).

## 1. 상태에 들어가는 것 (`ZoneSnapshot`)

| 구분 | 내용 |
|---|---|
| 우리 | 패, 몬스터와 그 엑시즈 소재(id), 마법·함정(세트 구분), 묘지, 제외, 엑스트라 덱(실전은 id로 보임), 덱 매수, LP, 일반 소환 여부, 배틀 페이즈 남음, 일반 소환 금지 이름 |
| 상대 앞면 몬스터 | id, 공격력/수비력, 표시 형식, 엑시즈 소재(id), 남은 방해 값, 전투 내성, 파괴 대체 비용 |
| 상대 마법·함정 | 앞면은 id와 남은 방해 값(지속 함정·필드 마법), 세트는 장수 |
| 상대 공개 영역 | 묘지(엑시즈 랭크 합 포함), 앞면 제외 |
| 상대 비공개 수 | 패 매수(공개된 패 id 따로), 뒷면 몬스터 수, 세트 마법·함정 수, 덱 매수, 엑스트라 매수, 합계 `OpponentHidden` |
| 이번 턴 효과 | 상대 드로우 감시(Maxx "C", Mulcharmy) |

에이전트만 아는 값(남은 방해, 전투 보호, 일반 소환 금지)은 `DuelZoneView`의 `Held` / `Guard` / `Enrich`로 채운다. 그래서 어디서 `Snapshot()`을 불러도 같은 값이 나온다. `PlanSnapshot()`은 이제 이 전체 상태를 그대로 돌려준다.

- 상태 기록(`_state.md`)의 매 턴 구간과 오프라인 덤프 앞부분에 "판단 입력" 절로 전부 출력한다.
- 결정 로그(jsonl `state`)에 양쪽 몬스터의 소재(`materials`), 뒷면 몬스터·세트 마법함정 수(`setMonsters`, `setSpells`)를 더했다. 학습 입력으로 쓴다.

## 2. 이 변경으로 고쳐진 판단

1. **소재로 붙은 카드도 덱·엑스트라 덱 밖으로 센다.**
   - 전에는 덱 잔량을 셀 때 엑시즈 소재를 빼먹었다(계획기, ValueModel의 `DeckRemaining`·`ExtraLeft` 모두).
   - 예: Duo Drive 아래 Ice 2장 + 패 Ice 1장이면 덱의 Ice는 0장인데, 2장 남은 것으로 봤다.
   - 예: F0 아래 Detonator 2장 + 묘지 1장이면 엑스트라의 Detonator는 0장인데, 2장 남은 것으로 봤다.
   - 실전은 우리 엑스트라 덱을 id로 그대로 쓴다.
2. **카드 선택, 제거 대상 가치, 엑시즈 즉시 소환, 함정 세트 판단이 상대 정보를 본다.** 전에는 이 판단들이 상대 몬스터와 그 남은 방해를 몰랐다(계획기만 알았다).
3. **앞면 카드 무효(Aggregator ③ 등)의 지금 이득에 상대 앞면 마법·함정도 들어간다.** 전에는 몬스터만 봤다. 실전 소재 떼기 쪽(`BestTurnNegateTarget`)은 원래 둘 다 봤으니, 이제 계획과 실전이 같다.
4. **상대 뒷면 몬스터가 전투 계산에 들어간다.** 오프라인 인자 `AgentDbOppSetMonsters`가 생겼다(실전은 원래 들어가 있었다).
5. **상대 남은 방해를 지속 함정·필드 마법에서도 읽는다.** 마법·함정 존의 효과 범위(SZONE/FZONE)를 본다.

이전 커밋(62c5de5) 빌드와 같은 입력으로 비교했다. 덤프 원문은 `out/<case>.<new|old>.md`이다.

| f0_det_mats | F0(소재 Detonator 2), 묘지 Detonator, 패 Ice | 엑스트라에 Detonator 2장 남은 것으로 봄, 계획 364.8 | 엑스트라 Detonator 0장(판단 입력 절), 계획 363.9: 같은 계획이고 Cross ③로 덱에 되돌린 Detonator를 다시 엑시즈 소환 |

## 4. 상태에는 있지만 아직 판단 항이 없는 것

상태에 들어간 정보 중 아래는 아직 가치 항이 읽지 않는다. 정보는 결정 로그에 남으므로 학습 단계에서 쓸 수 있다.

- **상대 비공개 수(패, 세트, 덱):** 우리 전개 중 상대 방해 위험(INTERRUPTION_RISK.md) 항이 이것을 쓴다. 그 항은 설계·검증만 하고 구현을 보류했다. 지금 이 수를 쓰는 곳은 미끼 순서(`OpponentPool`), Mulcharmy 상한, 상대 턴 제거 보류(`HoldContext.OppHand`)뿐이다.
- **상대 묘지·제외의 개별 카드:** F0 공격력(엑시즈 랭크 합) 말고는 쓰지 않는다. 상대 묘지 효과(묘지에서 발동하는 방해)는 위험 항에 들어갈 몫이다.
- **상대 엑스트라 매수:** 기록만 한다.
